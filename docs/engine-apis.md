# Engine module APIs

Generated from each engine engineer's final report after review and fixes. This is the integration reference for
the screen modules (PracticeUI, Library, Courses, Import, Settings). The sources in `LearnPiano/<Module>/` are
authoritative; open them for exact signatures. Every engine compiles and its unit tests pass (330 tests on the
iPad Air 13-inch simulator).

## Notation

### Public API

NotationScoreView(score:highlight:mode:staffSpace:showsFingering:palette:onSelectMeasure:onSelectRange:) is the SwiftUI view (scroll or page). NotationDisplayMode is .scroll or .page. NotationHighlightModel is the per-frame cursor and feedback state (positionTick, drawState(for:)). NotationScrollTransition holds the eased scroll state: ease(_:), isActive(at:), offset(target:at:), starting(from:at:duration:), isJump(fromTick:toTick:fromMeasure:toMeasure:pulseTicks:offsetChange:viewportWidth:sinceLastUpdate:) and next(from:to:displayedOld:viewportWidth:pulseTicks:sinceLastUpdate:at:) -> NotationScrollTransition?. Its constants are streamWindow = 0.25 s and streamJumpFraction = 0.25. NotationScrollSample(tick:measureIndex:offset:) holds the scroll inputs that next() compares. NotationScrollClock (@MainActor) has tick(at:), which returns the time since the last update, and lastUpdate. NotationLayoutCache.shared builds and caches NotationRenderPlan off the main thread. NotationCanvasPainter.draw paints a plan. NotationSelectionTracker handles tap and long-press-drag measure selection. NotationPalette.standard holds the colors. The layout, engraving and glyph types are unchanged.

### Integration notes

- Fixed [major] scroll freeze. Updates that come through one after another no longer restart an active NotationScrollTransition. The decision is now a pure function, NotationScrollTransition.next(from:to:displayedOld:viewportWidth:pulseTicks:sinceLastUpdate:at:). It never restarts a running transition for ordinary jumps, because that transition already follows the live target. A large move (more than 0.25 x viewport) may restart a transition, but only after it has run for half its duration. So even a stream of large jumps keeps moving.
- Jump detection now depends on timing (isJump has new defaulted parameters offsetChange, viewportWidth, sinceLastUpdate). An update arriving within 0.25 s of the previous one counts as part of a stream. Inside a stream, a forward move of more than pulse/8 counts as a jump only if the offset changes by more than 0.25 x viewport in that update. An isolated update keeps the old rule: more than pulse/8 ticks is a jump. Backward moves, non-finite ticks and moves to any measure other than the same or the next one are always jumps. Seeks, loop restarts, repeats and Wait-Mode steps after waiting are still eased.
- NotationScrollSample moved from NotationScoreView.swift to NotationHighlightModel.swift so it can be tested without the view. The new NotationScrollClock (@MainActor final class held in @State) records the time of the last update without invalidating the view each frame.
- New tests: testStreamedLargeStepsAreMotionNotJumps; testScrollTracksFastContinuousUpdates (60 consecutive 130-tick updates at 60 Hz, lag stays within one ease duration of travel, final lag 0); testScrollKeepsMovingThroughAStreamOfLargeJumps; testActiveTransitionIsNotRestartedByOrdinaryJumps; testScrollClockReportsIntervals. Ran with a macOS XCTest harness (Core + Notation built as a dylib, xcrun xctest): 41 tests, 0 failures.
- Contract deviations are unchanged from the previous report: measure numbers on every measure in scroll mode; ChordNote.accidental ignored (key signature plus measure memory only); tuplet numbers without brackets; no courtesy key or time signatures; beams never cross staves; x/8 simple meters follow pulseTicks literally; up-stem voice shifted right on seconds and unisons; empty pickup staff gets a whole rest; NotationPalette.standard duplicates the Theme RGB values.
- No Core, App or other-module edits. No new INTEGRATION shims.

### Integration notes

- Render cost [major, fixed]: AudioSynthVoice.render is now block-based. It uses complex-rotator partials, renormalized once per 32-sample sub-block. Envelopes update per sub-block with linear ramps. activePartialCount is set in start(), so partials at or above 0.45*sr are never generated, and decayed top partials (below -120 dB) are trimmed. Loops are scalar, 4 partials at a time, over a caller-owned flat Float bank with no SIMD generics. Measured on Apple-silicon macOS for 48 voices x 1 s: 0.166 s at -Onone (was 6.87 s for 36 voices) and 0.020 s at -O (was 0.42 s). Relative RMS error against an exact double-precision additive reference is about 1e-5. Setting SWIFT_OPTIMIZATION_LEVEL=-O for Debug is no longer required, but it is still a cheap win on A12-A14 iPads if the integrator wants it.
- Breaking API inside Audio: AudioSynthVoice() no longer exists. It is now AudioSynthVoice(bank: UnsafeMutablePointer<Float>), where the bank holds AudioSynthVoice.bankFloats floats owned by the caller. AudioSynthRenderState allocates the banks. render(into:start:count:scratch:) now takes a scratch buffer of at least subBlockLength floats. Nothing outside Audio used these types.
- Soft clip [major, fixed]: AudioSynthRenderState.softClip(_:) is identity up to knee 0.6, then k+(1-k)*tanh((|x|-k)/(1-k)). It is continuous, has slope 1 at the knee, is monotonic, stays below 1, and maps NaN to 0. A ramp test asserts that no adjacent-sample jump exceeds the input step.
- Strike-specific releases [major, fixed]: AudioRenderCommand has a new field strikeID: UInt32 (default 0), and the voice stores tag and strikeID. A noteOff with a non-zero strikeID releases only that strike's voice. An anonymous noteOff (strikeID 0) releases the voices of that key with the same producer tag, so player releases (tag 1) never cut immediate or on-screen notes (tag 0). allNotesOff still releases everything. DEVIATION from the review text: ID 0 is scoped to the producer's tag rather than to 'all voices of the key'. This is what stops player note-offs from cutting immediate notes, and the player's per-key reference counting is unchanged. AudioRenderCommandSink.makeStrikeID() hands out atomic IDs that skip 0. playChord gives every pitch its own ID and returns the IDs. AudioPianoSynth.play(chord:) returns [UInt32] and is @discardableResult. Sampler path: the render thread keeps a fixed-size key ledger (256 identified strikes plus a per-key anonymous-hold flag) and sends 0x80 only when the last strike of a key ends. When notes move back from the sampler to the synth, CC123 is sent to the sampler.
- Engine lifecycle [major, fixed]: before every engine (re)start (start(), configuration-change restart, interruption-ended restart), the synth calls renderState.killAllVoices(), which also resets the click voice and the sampler ledger and clears any pending requestReset. It also calls AudioCommandQueue.discardStale(atHostTime: now), which keeps only future-dated note/click commands and the cancel/flush control commands, in their original order. noteOn, play(chord:) and click() now call ensureRunning(). noteOff and allNotesOff send nothing while the engine is stopped.
- NEW hook to wire: AudioPianoSynth.addEngineStopHandler(_:) -> token (with removeEngineStopHandler). Handlers run on stop() (before engine.stop), on interruption .began, on a failed configuration-change restart, and on media-services reset. AudioScorePlayer registers itself: it pauses and keeps its position, then calls its new onInterrupted callback. INTEGRATOR: wire player.onInterrupted to PracticeSession's pause so the session state matches. AudioMetronome registers itself too. It cancels any count-in (the completion does NOT fire), halts clicks, and stays active, so it follows the player's next run. An independent run (no player) needs a new start(). The integrator should still call player.pause() (and session pause) before synth.stop() for app-lifecycle stops.
- Tie continuation at run/lap start [major, fixed]: AudioPlaybackItem has a new field continuations: [AudioPlaybackContinuation] (note with the tie chain's final endTick, attackTick, tiedFromTick). It is recorded where the plan extends an open tie, and endTicks are fixed up once all chains are complete. AudioPlaybackJob strikes item.continuationsToStrike(lapStartTick: mapper.lapTickRange(lap).lowerBound) for each occurrence. Lap 0's lower bound is startTick, so play(fromTick:)/seek/resume on a continuation works. Release math is mapper.releaseElapsed with the chain end, cut at the lap end. DEVIATION: the strike condition is tiedFromTick (the previous link of the chain) < lapStart, not attackTick < lapStart. With chained ties (A->B->C) the attackTick rule would re-strike C after B was already struck in the same lap. A continuation is also skipped when the key is already sounding in the job (for example, adopted from a re-time hand-over), so a re-time never re-attacks a tied note. A run that starts in the middle of a sounding note (not on an event tick) still does not sound that note. This is the same as for untied notes.
- Unchanged earlier deviations: the count-in completion fires about 60 ms (or half a pulse) before the downbeat, and the exact downbeat goes through AudioPianoSynth.pendingTransportStartHostSeconds. onEventStarted fires only for audible events. audibleHands == nil means the transport runs with all hands muted. stop() rewinds to the loop start. The speed clamp is 0.1...2.0.
- Tests added in LearnPianoTests/AudioTests.swift. Voice: exact-reference accuracy, Nyquist-guard partial count, long bass note decays and frees itself. Render-cost budget (best of 3): 48 voices x 1 s < 0.15 s without DEBUG, < 0.75 s with DEBUG. This relies on Xcode's default DEBUG compilation condition in the Debug config. Clip: ramp continuity, monotonicity, bounds. Releases: earlier chord release vs newer strike (60 still held at 1.2 s), tag scoping, sampler key ledger, plus discardStale. Ties: loop lap strikes at 0/4/6 s, run started on a continuation strikes at elapsed 0, chained ties strike once, and no re-strike while a key is adopted. Engine stop pauses the player and calls onInterrupted. The existing voice tests were ported to the bank-backed voice.

### Integration notes

- NEW INTEGRATION HOOK (app playback heard by the mic): App/PracticeUI must call hub.noteAppSounding(pitches: event.pitches, from: InputClock.now, until: InputClock.now + eventSeconds) inside ScorePlaybackControlling.onEventStarted (Just Play accompaniment, Listen). It must call hub.noteAppSounding(chord) next to every playImmediately(chord) (Wait Mode other hands), and hub.clearAppSounding() on stop or seek. Times use the Input clock (InputClock.now = systemUptime = NoteInputEvent.time). The router then drops microphone note-ons on those keys and on their octave, 12th and double octave (echoIntervals [0,12,19,24]) for the interval plus a 150 ms tail and a 30 ms lead, and swallows the matching mic note-off. MIDI and on-screen input are never gated.
- Behaviour change in .both mode: a microphone note-on is dropped (and its later off swallowed) while the key, or a key 12/19/24 semitones below it, is MIDI-held, or when its MIDI note-on is within 0.35 s of the mic event. The mic no longer becomes a co-holder, so the MIDI note-off is forwarded immediately. Tunable via InputHub.echoConfiguration (InputHubEchoConfiguration). InputHubTests.testDuplicateKeyFromTwoSourcesIsDeliveredOnce was updated: heldNotes is empty right after the MIDI off.
- Mic timestamps: InputPitchPipeline re-anchors to the caller's startTime on every process() call. Disagreements up to 2 ms are ignored as jitter. Larger ones shift the clock (drift). More than one hop (23 ms) counts as a discontinuity: pending samples are dropped and the tracker's flux history is reset, so the jump is not read as an onset. InputMicrophoneSource needs no change, as long as it keeps passing each tap buffer's host-time start.
- Tracker or detector changes the integrator should know about. Candidates remember their first strong frame, and only those that appear at or 1 frame before the earliest onset of the open window may confirm. A new note's three lowest partials must also have gained at least 1.4x energy over the spectrum just before the window opened, so a masked 5th chord tone cannot fire on an unrelated onset. A key released less than 0.3 s ago that comes back without its own salience jump resumes silently (no note-on). Its later off reaches the hub as a stray off, which InputHeldNoteTracker drops. A retrigger of a sustained note needs a 2x own-salience jump (instead of 1.5x) while a partial-sharing new note starts in the same window. Onsets now also require positive flux greater than negative flux and frame energy of at least 0.9x the previous frame, so a note being cut off is not an attack.
- Detector changes: detect(spectrum:sounding:reference:) takes the tracker's sounding notes and pre-onset spectrum (the pipeline wires both). A sounding note is never demoted to a sub-octave unless that octave is also sounding. A fundamental-less sub-octave of a sounding note is skipped as a candidate; this was the real cause of the C2 phantom, because C2 won outright as a 'missing fundamental'. The octave-down correction needs the lower fundamental to be at least 0.25x the winner's strongest partial, and does not count odd partials that are sounding notes or other strong candidates. Rejected harmonic ghosts no longer use up a polyphony slot (bounded to 3x maxPolyphony rounds). A candidate that rises over a held, non-rising note is exempt from the ghost rule (ghostRiseRatio 2.2).
- Measured on the reviewer's scenario (5 chords x 4 three-note melodies, 1/k partials, B=3e-4): 20/20 correct now, versus 13/20 wrong with 71 extra note-ons and 62 early releases before. The static C3-G3-E4 for 3 s no longer releases C3 mid-sustain. The 5-chord-plus-new-note probe gives only the new note. Soft melody (-10 dB) over a loud chord went from 15/20 wrong to 8/20 wrong. Per-frame cost is 0.073 ms optimised and about 10.5 ms at -Onone on this Mac (frame budget 23 ms).
- Known limitations (all present before this change): octave doublings struck together (C3+C4) are often detected as one note, or as the octave ghost of the same pitch class. Chord changes can add an octave ghost of a new chord tone (same pitch class). Wait Mode's pitch-class matching tolerates both. The note-on stamp can be up to ~70 ms late for some attacks.
- Unchanged deviations, still to be reported: framesToConfirmOn = 3 (contract says 2). One MIDI input port, no virtual destination endpoint. .both cannot be persisted through UserSettings.preferredInput. The Input views use system colors and fonts, not App/Theme.

### Integration notes

- FIX (major 1, Wait gap feedback): `complete(_:now:)` now clears `satisfied` and `windowStart` after building the record. During `.gap`, `missingPitches`, `satisfiedPitches` and `feedback()` take satisfaction for the `to` step from `earlyAttacks` only, through a private `isSatisfied(_:)`. A repeated C4 now shows as `.expected` with missing == [C4] during the gap. The just-played event keeps its `.correct` flash through `recentCorrectEvents`. Test: `testRepeatedNoteIsExpectedAgainDuringGap`.
- FIX (major 2, per-settings segments): a change to mode, hands, speed or loop while a statistics session runs (playing, counting in or paused) now ends that session first, using the PREVIOUS settings (`endSession(reachedEnd: false, settings: previous)`). One `PracticeSessionRecord` goes out through `onSessionEnded`. The transport then continues at the cursor in a fresh session, and the on-screen `statistics` and `practicedSeconds` reset to the new segment. A segment with no practiced time and no records emits nothing. Other structural changes keep the running session: octave tolerance, chord and timing windows, rest scale, playOtherHands. `play()` while paused begins a fresh session if a settings change ended the old one. Renamed test: `testSessionSpeedChangeEndsSegmentAndKeepsPosition`. Probe regression test: `testSessionModeChangeReportsEachSegmentWithItsOwnSettings`. Integrator impact: `UserProfile.record` now runs once per segment, so `SongProgress.sessions` counts segments.
- FIX (major 3, reachedEnd): new private `coveredFromStart`. It is set when a fresh session begins at or before the first material step with `loop == nil`. Any begin at the piece start (restart, play after finished) and any jump of the running session back to the very start set it again. It is cleared by a fresh session that starts mid-piece (including after a segment-ending settings change), by any seek or phrase skip forward past the cursor, and by a Just Play `.resyncRequested` that moves ahead of the transport position. `finishSession` reports `reachedEnd: coveredFromStart`. `endSession` additionally forces false for `.listen`. `PracticeSummaryBuilder.summary` forces `reachedEnd = false` for `.listen`. Tests: `testSessionReachedEndRequiresCoveringThePiece`, `testSessionPhraseSkipForwardLosesCoverage`, `testSessionJustPlayForwardResyncLosesCoverage`, `testSessionListenNeverReachesEnd`, plus a listen assertion in `testSummaryBuilderMapsModes`.
- DEVIATION (deliberate, small): rebuilds for non-summary settings (octave tolerance, windows, rest scale, playOtherHands) resume at the cursor without skipping notes, so they KEEP `coveredFromStart` rather than clearing it. Clearing it would deny completion to a learner who toggles octave tolerance mid-piece. Every rebuild that changes mode, hands, speed or loop now starts a fresh session, so a mid-piece restart there clears coverage as the reviewer asked. Backward seeks keep coverage. A forward seek that lands before an earlier high-water mark still clears it (conservative).
- Just Play: a learner who starts at the beginning and lets the transport run to the end still gets reachedEnd=true even with few hits (Core then records honest `bestAccuracy` = actual accuracy at full speed). Requiring a minimum hit rate is not in the contract, so it was not added.
- Unchanged earlier notes: held keys are not credited by default (`PracticeWaitOptions.creditsHeldKeys`). The chord window defaults to .lenient (.strict is available). Just Play summary `stepsCorrect` counts correct+early+late (`PracticeStatistics.strictAccuracy` is available if the integrator wants ARCHITECTURE's literal correct/expected). Wait Mode never counts in. Speed snaps to 0.05 steps in 0.25…1.0. `audibleHands` is nil when the learner plays both hands or playOtherHands is off; Audio must treat nil as 'mute all'.

### Integration notes

### Integration notes

- All 6 majors are fixed. Typecheck passes. The parsecheck harness (the brief's exact swiftc command) exits 0: 'All 42 files parsed cleanly and round-tripped'. A scratch script confirmed the new per-staff voice rule gives the same result as the old rule on every bundled song, so no bundled file changes hands.
- Unit tests were also run, not just written. I compiled Core and Parsers as a testable 'LearnPiano' dylib with swiftc, built ParsersTests.swift against XCTest and ran it with `xcrun xctest`. Result: 47 tests, 0 failures. Scratch build outputs were deleted.
- Import module (wave 2) must wire this: ParsersCompactScoreImporter(firstMeasureNumber:isFinalPage:pieceHasPickup:). For a multi-page transcription, pass isFinalPage: false for every page except the last. For pages after page 1, pass pieceHasPickup set to page 1's "pickup" value. The final measure may now be short only when it is the end of the piece AND a pickup was declared (doc rule 3). A document with no pickup must therefore have a full final measure. The defaults (true, nil) keep standalone documents working.
- Import concatenation: the LPC reader now folds time/key/tempo written on a document's first measure into the score's initial values; measures[0] no longer carries them. When concatenating pages, the Import module must compare each later page's initialTime/initialKey/initialTempoBPM with the values in force at the end of the previous page. Where they differ, it must write them as changes on that page's first measure.
- MusicXML multi-part behaviour changed. Parts that land in the same hand now get separate voice numbers: each later part's voices are numbered after the highest voice the earlier parts used in that hand. Each such merge logs a warning that names the parts. When any part has two staves, a single-staff part goes to the hand its clef suggests (bass clef = left, otherwise right), so a treble melody listed after the piano no longer lands in the left hand. When every part is single-staff, the old rule still applies: the first part is the right hand, the rest the left. The old warning 'parts after the second are merged into the left hand' is replaced by the per-hand merge warning.
- Known limit: the exporter still writes at most 4 voices per staff (any voice above 4 shares voice 4). A MusicXML file whose merged parts use more than 4 voices in one hand may therefore show overlap errors after export and re-import. Before this fix such parts already collided at import.
- Two-staff voice rule: voice numbers decide the hand only when every voice id is numeric (1-8), at least 80% of staff-1 notes use voices 1-4, at least 50% of staff-2 notes use voices 5-8, and at least one staff-2 note uses voices 5-8. Otherwise the staff decides the hand. This is ParsersMusicXMLScoreBuilder.usesConventionalVoices.
- Clef deviation (now reported): Core has no clef concept. The importer reads clefs only to place single-staff parts, and the notes of a staff keep their hand. A mid-score clef change now produces one measure-numbered info diagnostic per part. Several bundled songs (3 parts) show it; it is info only and does not fail parsecheck.
- MIDI: track names are now matched as whole words. Dots are stripped first, so 'l.h.' counts as 'lh'. Left words: left, links, linke, lefthand, lh, bass, gauche, sinistra. Right words: right, rechts, rechte, righthand, rh, treble, droite, destra. A name containing words for both hands gives nil. Track names decide the hands only when at least 2 streams are used, every used stream has a name, and the names cover both hands. A single stream is always split by pitch.
- ZIP/MXL changes: decompression uses a fixed 64 KiB chunk, and memory is reserved for at most the declared size or 64 MiB, whichever is smaller. Decompression stops with ParsersZipError.tooLarge(entry:limit:) once output passes ParsersZipArchive.maxEntrySize (64 MiB), and stops with .inflateFailed as soon as output passes a known declared size. A declared size above 64 MiB is refused before any work. ZIP64 markers (0xFFFF entry count, 0xFFFFFFFF size or offset in the EOCD, central or local headers) throw the new .zip64Unsupported. The MXL importer turns both into ImportError.malformed.
- Exporter: measure 0 now writes score.timeSignature(atMeasure: 0), keySignature(atMeasure: 0) and tempoBPM(atMeasure: 0), so time, key and tempo overrides stored on measures[0] survive export and re-import. Verified: a 3/4 measure at 60 BPM under a 4/4, 100 BPM score header plays 6.0 s before export and 6.0 s after re-import.
